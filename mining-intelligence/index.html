CONCEPT ARCHITECTURE · V0.3
No es otro dashboard minero

Es una disciplina operacional para decidir bajo incertidumbre.

El problema no es que falten datos o modelos. El problema es que una salida plausible puede parecer más cierta de lo que realmente es. La capa separa observación, interpretación, forecast y decisión para que nunca se mezclen silenciosamente.

01 / PROVENANCE

Toda afirmación debe poder volver a su fuente.

Fuente, evidencia, método, timestamp, versión y revisor permanecen ligados al claim.

Source → Evidence → Claim
02 / UNCERTAINTY

La incertidumbre no se esconde.

Lo inferido no se presenta como observado. Un forecast nunca se muestra como hecho.

Fact ≠ inference ≠ forecast
03 / REVERSIBILITY

La calidad de una decisión incluye poder revisarla.

Cuando cambia la evidencia, el sistema conserva qué cambió, por qué y qué decisión queda afectada.

Versioned & revisable
04 / HUMAN KEY

La IA no obtiene autoridad por sonar segura.

En decisiones de alto impacto, la acción requiere una aprobación humana explícita.

impact = high ⇒ human
Gates de realidad y revisabilidad

Nada cruza por plausibilidad.

Una recomendación puede ser convincente y estar equivocada. Por eso cada transición exige condiciones explícitas. El sistema está diseñado para reducir saltos de certeza, no para producir respuestas más persuasivas.

GATE 01REALITY

¿Existe evidencia observable?

Antes de afirmar, el sistema pregunta si existe una base verificable y si la fuente tiene el alcance suficiente para sostener el claim.

  • fuente identificada
  • evidencia enlazada
  • vigencia y cobertura conocidas
GATE 02TIBURÓN

¿Cómo romperíamos este razonamiento?

El revisor adversarial intenta encontrar lo que la primera pasada no quiso ver: contradicciones, dependencia circular, supuestos implícitos y exceso de confianza.

  • contraevidencia
  • supuestos ocultos
  • alternativas explicativas
GATE 03META-HARNESS

¿Tiene permiso epistemológico para avanzar?

Reglas deterministas controlan la transición. Un hecho sin evidencia bloquea. Un forecast sin baseline pierde peso. Un claim público exige revisión competente.

  • PASS / CONDITIONAL / HOLD
  • reglas reproducibles
  • hallazgos auditables
GATE 04HUMAN KEY

¿Debe una persona autorizar la acción?

El objetivo es aumentar la calidad de la decisión humana, no desplazar responsabilidad en decisiones de capital, operación o seguridad.

  • impacto declarado
  • alternativas visibles
  • aprobación explícita

La interfaz no sólo muestra “qué hacer”. Permite recorrer por qué podría hacerse, qué podría invalidarlo y qué alternativa conserva más opcionalidad.

Revisabilidad

Un sistema serio debe poder cambiar de opinión sin borrar su historia.

Trazabilidad no significa sólo “tener fuentes”. Significa poder reconstruir qué evidencia existía, qué versión del modelo se usó, qué reglas estaban activas y por qué una decisión fue razonable en ese momento.

  • Claims versionados y relaciones supersedes / invalidates / supports.
  • Incertidumbre explícita y preservada en el historial.
  • Auditoría del gate que permitió o bloqueó el avance.
  • Capacidad de reabrir decisiones cuando cambia evidencia material.
